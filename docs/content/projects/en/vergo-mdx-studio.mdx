Writing website content from inside a notes app usually means guessing how the editor's Markdown will turn into the page that actually ships. Vergo MDX Studio removes the guesswork for authors who publish MDX to a static site: the preview, the compiler and the pre-flight checks all run inside Obsidian, and the final step is a review, never a silent publish.

## How do you write site-ready MDX inside Obsidian?

Run the **New MDX note** command or right-click a folder and pick it. The plugin asks for a title and a language, then creates a `.mdx` file with the correct frontmatter and opens it in the normal editor. From there you write Markdown and the site's own components, and `.mdx` files behave like any other note in the vault.

The preview side pane follows what you type. It rebuilds the page shell the site uses — title, Quick-answer box, tags, table of contents, FAQ and reading time — so the result looks like the published entry rather than a generic Markdown render.

## How does the preview match the live site?

The pane renders into an iframe using the website's own class names and stylesheet. By default the plugin fetches the live stylesheet and uses it only when it already matches the current design; otherwise, or when offline, it falls back to a bundled snapshot, so the preview is never unstyled. Direction (RTL/LTR) comes from the `lang` frontmatter, and a toolbar toggle switches dark and light.

Compilation uses the same compiler the site build runs, with GFM enabled. When something fails, the error is reported at the exact file line and column with a plain-language hint — for example, that MDX reads a bare `<` as the start of a JSX tag.

## What gets validated before a page is sent?

Before anything is uploaded, the plugin applies the same kind of checks the dashboard uses:

| Check | What it looks at |
| --- | --- |
| Title length | 30–60 characters for search results |
| Summary | 70–165 characters, used as the Quick answer |
| Body | flags an unwanted H1 and empty image alt text |
| Frontmatter | `lang` must be `en` or `fa` |
| Media | every referenced file exists in the vault |
| Compile | an error disables sending until it is fixed |

Only the site's built-in components are accepted, and expressions that use server APIs are rejected, mirroring the server's own policy so problems surface in the editor first.

## How does media reach the server?

References are collected from Markdown images, HTML/JSX `src` and `poster` attributes, and the `image` frontmatter key. Each file is hashed, the plugin asks the server which names are missing, and only those are uploaded. The references are then rewritten to `/media/studio/<hash>.<ext>` before the page is submitted.

<Callout type="tip" title="Nothing is live until you approve it">
The server stores the submission and re-compiles the MDX. Staged media is moved into the public assets only when you approve the page in the dashboard Inbox.
</Callout>

## How do you install and run it locally?

Copy `main.js`, `manifest.json` and `styles.css` into `<vault>/.obsidian/plugins/vergo-mdx-studio/`, then reload Obsidian. To build from source you need Node.js 22 or newer:

```bash
git clone https://github.com/vergoboy/vergo-mdx-studio.git
cd vergo-mdx-studio
npm install
npm run build      # typecheck + production bundle -> main.js
npm test           # vitest run
```

The plugin requires Obsidian 1.5.0 or newer and a Studio token from the site's dashboard, entered under Settings ▸ Vergo MDX Studio.
